## 第一部分：项目整体介绍

### 1. 项目是做什么的

一句话：把北京市 12 个监测站点 4 年的空气质量 CSV，经过 HDFS 存储、Hive 建表、Spark SQL 统计，把结果放进 MySQL，再由 Spring Boot 提供接口、Vue3 做成大屏和查询页。

它不是一个"网页展示几个静态图"的项目，而是有一条可以完整复跑的数据链路：原始 CSV → HDFS → Hive 外部表 → Spark SQL 聚合 → CSV 导出 → MySQL → 接口 → 页面。

### 2. 为什么选城市空气质量

- 数据公开、可核实：UCI 官方数据集，有 DOI 和 CC BY 4.0 许可，不用自己编数据。
- 数据天然是"时间 + 站点"的二维结构，特别适合做分组聚合（GROUP BY）和时间趋势分析。
- 字段里有缺失值（NA），正好可以讲数据质量与清洗口径，而不是"数据很完美"的空壳项目。
- 结论直观：柱状图看站点差异、折线图看月和小时变化，老师一眼能看懂。

### 3. 项目解决了什么问题

- 数据散在 12 个 CSV 里，没法直接用 SQL 查 → 用 HDFS 统一存放、Hive 建表。
- 原始数据有缺失、有极值，直接平均会失真 → 明确"只用非空值做分母"的统计口径。
- 统计结果需要给非技术用户看 → 后端接口 + 可视化页面。

### 4. 数据来自哪里

- 数据集：Beijing Multi-Site Air Quality Data Set
- 来源：UCI Machine Learning Repository，ID 501
- DOI：10.24432/C5RK5G
- 许可：CC BY 4.0（可共享、可改编，需署名）
- 规模：12 个 CSV，420,768 条小时级记录，2013-03 至 2017-02
- 单位（以官方数据字典为准）：六种污染物都是 μg/m³，温度 ℃，气压 hPa，风速 m/s，降水 mm

### 8. 1 分钟现场介绍话术

> 我的项目叫《城市空气质量大数据分析与可视化系统》。数据来自 UCI 官方的北京市多站点空气质量数据集，包含 12 个监测站点、42 万条小时级记录，时间从 2013 年 3 月到 2017 年 2 月。
>
> 整个流程是：原始 CSV 先上传到 HDFS，用 Hive 建外部表把它映射成可以查询的表；然后用 Spark SQL 做三类聚合——按站点、按年月、按小时，每种污染物都算出平均值和有效样本数；结果导出成 CSV，再导入 MySQL；最后由 Spring Boot 提供四个查询接口，Vue3 加 ECharts 做成大屏和查询页。
>
> 项目里我特别处理了两个数据问题：一是 CSV 表头不能让 Spark 当成数据，二是缺失值 NA 不能当成 0 参与平均，所以所有平均值都只除以有效样本数。

### C. Python 数据质量检查

#### Q9. 你的数据质量检查具体做了什么？

**考查知识点：** 脚本的实际功能。

**结合源码的位置：** scripts/data_quality_check.py 的 main() 组装了 5 类检查：check_missing、check_duplicates、check_anomalies、check_special_values。

**通俗解释：** 五件事：看规模、看缺失、看重复、看异常、看特殊值。

**建议回答：** 脚本先读 12 个 CSV 拼成一个大表，然后做五类检查：总行数和站点数、每个字段的缺失数量和比例、按站点加时间判重、负浓度和气象越界的数量、还有 999、500、10000 这些可疑值的分布。结果输出成一份 Markdown 摘要和一个 JSON，JSON 是留给后面 Spark 对照用的。

**可能的追问：** 为什么用 Python 还要用 Spark 再算一遍？——Python 结果是基准，Spark 复算用来验证大数据链路算得对不对，两边数字必须一致。

#### Q10. 重复记录是怎么判断的？为什么不是按行号 No 判断？

**考查知识点：** 主键思维。

**结合源码的位置：** check_duplicates() 里用的是 duplicated(subset=["station", "observation_time"], keep=False)。

**通俗解释：** No 只是文件内行号，不能当唯一标识。

**建议回答：** 因为 No 字段在每个文件里都是从 1 开始的，12 个文件各有一份 1 到 35064，不能当全局主键。一条记录真正唯一的标识是"哪个站点 + 哪个小时"，所以我用 station 和 observation_time 两列组合来判断重复。

**可能的追问：** 结果是多少？——0 条重复、0 组。

### D. HDFS、Hive、外部表与 Spark SQL

#### Q12. 为什么要用 HDFS？数据不能直接放本地吗？

**考查知识点：** 分布式存储的意义。

**结合源码的位置：** bigdata/ddl/01_hive_ods.sql 的 LOCATION '/aq/ods/air_quality'；README 第 10 节的上传步骤。

**通俗解释：** HDFS 让多个节点都能访问同一份数据，也是 Hive 表的落地位置。

**建议回答：** 技术上本地也能放，但 Hive 外部表需要指向一个 HDFS 路径，Spark 也从 HDFS 读，这样存储和计算是分开的。另外 HDFS 有副本机制，文件不会因为一台机器坏了就丢。我的目录分两层：/aq/ods 放原始 CSV，/aq/ads 放统计结果。

**可能的追问：** 副本数是多少？——这个环境是默认配置，我没有改过，具体值需要上虚拟机用 hdfs fsck 或看 hdfs-site.xml 确认（不要硬答 3）。

#### Q13. 内部表和外部表有什么区别？你为什么用外部表？

**考查知识点：** Hive 表的核心概念。

**结合源码的位置：** 01_hive_ods.sql 和 05_hive_ads.sql 里都写了 CREATE EXTERNAL TABLE 加 LOCATION。

**通俗解释：** 外部表删表不删数据，内部表删表连数据一起删。

**建议回答：** 内部表由 Hive 管理数据目录，DROP 表会把数据一起删掉；外部表只记录元数据，DROP 表只删表定义，HDFS 上的文件还在。我用外部表是因为原始数据和统计结果都是文件形式的资产，不希望一次误操作把数据删了。

**可能的追问：** 那 DROP 之后重新建表还能查到数据吗？——能，只要 LOCATION 路径没变。

#### Q14. OpenCSVSerde 是干什么的？为什么不用默认的 ROW FORMAT DELIMITED？

**考查知识点：** CSV 解析细节。

**结合源码的位置：** 01_hive_ods.sql 的 ROW FORMAT SERDE 和三个 SERDEPROPERTIES。

**通俗解释：** 原始 CSV 的字符串带双引号，默认方式会把引号也读进去。

**建议回答：** 原始文件里字符串字段是带双引号的，比如 "Aotizhongxin"、"NNW"。如果只用 ROW FORMAT DELIMITED FIELDS TERMINATED BY 逗号，Hive 会把引号当成内容的一部分，站点名就变成带引号的字符串，后面按站点分组就会出问题。OpenCSVSerde 能按 CSV 规则处理引号和转义，所以我用它，并指定了分隔符逗号、引号双引号、转义符反斜杠。

#### Q15. 表头是怎么处理的？为什么 Spark 会多出 12 行？

**考查知识点：** 是否真的踩过并解决过这个坑。

**结合源码的位置：** 01_hive_ods.sql 的 TBLPROPERTIES skip.header.line.count 等于 1；02_hive_view.sql 的 WHERE LOWER(no) 不等于 'no'。

**通俗解释：** Hive 认 skip.header 参数，Spark 不认，所以 Spark 把 12 个表头当成了数据。

**建议回答：** Hive 建表时我加了 skip.header.line.count 等于 1，Hive 查询是 420,768 行，正确。但用 Spark SQL 查同一张表得到 420,780，正好多 12 行，就是 12 个文件的表头。原因是这个属性只在 Hive 执行引擎生效，Spark 扫描文件时不识别。我的处理是建了一个视图 ods_air_raw_v，用 WHERE LOWER(no) 不等于 'no' 把表头行过滤掉，之后 Hive 和 Spark 查视图都是 420,768。

**可能的追问：** 为什么用 LOWER？——第一次我写的是 no 不等于 'no' 没生效，因为表头里是大写的 "No"，改成 LOWER(no) 才匹配上。

### E. SQL 统计逻辑与口径

#### Q17. AVG 和 COUNT 是怎么算的？NA 会不会被当成 0？

**考查知识点：** SQL 聚合与空值语义。

**结合源码的位置：** 04_spark_ads.sql 里的 CAST(pm25 AS DOUBLE) AS value、ROUND(AVG(value), 2)、COUNT(value)。

**通俗解释：** 字符串 NA 转数字会变成 NULL，NULL 不参与 AVG 和 COUNT。

**建议回答：** 原始表里字段都是字符串，NA 就是两个字母。我用 CAST(pm25 AS DOUBLE) 转成数字，NA 转不过来会变成 NULL。SQL 的 AVG 会自动忽略 NULL，COUNT(value) 也只数非空值，所以缺失值不会被当成 0 参与平均。

**可能的追问：** 如果 NA 被转成 0 会怎样？——均值会被明显拉低，比如 CO 缺 4.92%，均值就偏低了，而且样本数也会虚高。

---

#### Q18. 为什么平均值要除以有效样本数，而不是总记录数？

**考查知识点：** 统计口径。

**结合源码的位置：** 04_spark_ads.sql 同时输出 AVG(value) 和 COUNT(value)，分别对应 avg_value 和 valid_cnt。

**通俗解释：** 没测到的数据不能算进分母。

**建议回答：** 因为缺失的意思是"这个小时没测到"，不是"测到 0"。如果除以总行数，等于把没测到的时间当成 0 浓度，平均值会系统性偏低。所以分母只算非空值，同时把有效样本数一起输出，看的人就知道这个平均值是基于多少条数据算的。

**可能的追问：** 那不同站点能直接比吗？——能比，但要同时看有效样本数，样本数差太多时结论要谨慎。

#### Q19. 三张统计表为什么分别是 72、288、144 行？

**考查知识点：** 维度组合数量。

**结合源码的位置：** 04_spark_ads.sql 三个 GROUP BY；docs/10-stage3-ads-mysql.md 第 2 节。

**通俗解释：** 12 站乘 6 污染物等于 72；48 个月乘 6 等于 288；24 小时乘 6 等于 144。

**建议回答：** 因为三张表的粒度不同。站点表是 12 个站点乘 6 种污染物等于 72 行；月度表是 48 个月乘 6 种污染物等于 288 行；小时表是 24 个小时乘 6 种污染物等于 144 行。行数是维度组合数，不是随便定的。

**可能的追问：** 为什么是 48 个月？——2013 年 3 月到 2017 年 2 月正好 48 个月。

#### Q20. 为什么站点、月度、小时三种聚合的 PM2.5 有效样本数加起来都是 412,029？

**考查知识点：** 是否理解"同一批数据的不同分组方式"。

**结合源码的位置：** 三张表都来自同一个 aq_long 视图，只是 GROUP BY 的字段不同。

**通俗解释：** 同一堆苹果，按颜色分、按大小分、按产地分，总数都是那些苹果。

**建议回答：** 因为三张表统计的是同一批 PM2.5 非空记录，只是分组维度不同。按站点分是 12 组，按月分是 48 组，按小时分是 24 组，但每一组的 COUNT 加起来还是全部非空记录的条数，所以都是 412,029。这其实是一个很好的自检：如果三个和不相等，说明有重复计数或者漏计。

**可能的追问：** 这个数字和 Python 算的一致吗？——一致，Python 里 PM2.5 去掉空值后是 412,029 条。

### H. Controller、Service、Mapper 与 MyBatis

#### Q27. 污染物参数是怎么校验的？如果传个乱码会怎样？

**考查知识点：** 参数校验与防御式编程。

**结合源码的位置：** StatsServiceImpl.java 的 checkPollutant() 方法和 ALLOWED 常量。

#### Q29. MyBatis 的注解 SQL 是怎么写的？井号占位符和美元占位符有什么区别？

**考查知识点：** MyBatis 基础。

**结合源码的位置：** StatsMapper.java，例如 selectStationStats 上的 @Select 和井号大括号 pollutant 占位符。

**通俗解释：** 井号是预编译占位符，美元符号是字符串拼接，后者有注入风险。

**建议回答：** Mapper 接口上直接用 @Select 写 SQL，参数用井号大括号占位，MyBatis 会把它变成 JDBC 的 PreparedStatement 参数，值不会拼进 SQL 文本，所以能防注入。如果用美元符号大括号，就是直接字符串替换，传个奇怪的值就可能改掉 SQL 语义，项目里没有这么用。

**可能的追问：** 结果怎么映射成对象？——SQL 里用 AS 起了别名，比如 avg_value AS avgValue，和 VO 的属性名对上，再加上 map-underscore-to-camel-case 配置。

### 1. Hive 外部表定义

文件：bigdata/ddl/01_hive_ods.sql

~~~sql
CREATE EXTERNAL TABLE aq_air.ods_air_raw (
  no STRING, year STRING, month STRING, day STRING, hour STRING,
  pm25 STRING, pm10 STRING, so2 STRING, no2 STRING, co STRING, o3 STRING,
  temp STRING, pres STRING, dewp STRING, rain STRING, wd STRING, wspm STRING,
  station STRING
)
ROW FORMAT SERDE 'org.apache.hadoop.hive.serde2.OpenCSVSerde'
WITH SERDEPROPERTIES ("separatorChar" = ",", "quoteChar" = "\"", "escapeChar" = "\\")
STORED AS TEXTFILE
LOCATION '/aq/ods/air_quality'
TBLPROPERTIES ("skip.header.line.count" = "1");
~~~

**逐块解释：**

- EXTERNAL TABLE：建外部表，删表不删 HDFS 文件。
- 18 个字段全用 STRING：先把原始文本原样装进来，NA 保持两个字母，不让 Hive 自作主张转换。
- OpenCSVSerde：按 CSV 规则解析，能处理字段外层的双引号。
- LOCATION：这张表的数据在 HDFS 的 /aq/ods/air_quality 目录下，12 个 CSV 都放这里。
- skip.header.line.count=1：让 Hive 读文件时跳过第一行表头。

**为什么这么写：** 如果字段直接定义成 DOUBLE，Hive 遇到 NA 会转成 NULL 或者报错；先用 STRING 接住，后面用 CAST 控制转换时机，更安全。

**输入输出：** 输入是 12 个 CSV 文件；输出是一张可以 SELECT 的表，COUNT 应为 420,768。

**改错会怎样：** 去掉 EXTERNAL 会变成内部表，DROP 时数据文件一起没了；去掉 skip.header，行数会变成 420,780；不用 OpenCSVSerde，站点名会带引号。

**可能追问：** 为什么列名不叫 PM2.5？——Hive 列名不能带点，点会被当成库名.表名.字段名的分隔符，所以映射成 pm25，注释里写清对应关系。

### 2. 过滤 CSV 表头的视图

文件：bigdata/ddl/02_hive_view.sql

~~~sql
CREATE VIEW aq_air.ods_air_raw_v AS
SELECT no, year, month, day, hour, pm25, pm10, so2, no2, co, o3,
       temp, pres, dewp, rain, wd, wspm, station
FROM aq_air.ods_air_raw
WHERE LOWER(no) <> 'no';
~~~

**逐块解释：**

- 视图不存数据，只存一条 SQL 定义。
- LOWER(no) <> 'no'：表头那一行的 no 值是字符串 No，转小写后等于 no，就被过滤掉；正常数据行的 no 是数字字符串，比如 1、2，不会被误杀。

**为什么这么写：** Hive 的 skip.header 参数 Spark 不认，Spark 查原表会多 12 行。与其改数据，不如加一层视图统一口径，Hive 和 Spark 都查视图。

**输入输出：** 输入是原表；输出是去掉表头的数据视图，420,768 行。

**改错会怎样：** 如果写成 no <> 'no'，因为大小写不匹配，表头过滤不掉，Spark 还是 420,780。

**可能追问：** 视图会影响性能吗？——视图只是把 SQL 包了一层，执行时展开，对这个数据量没有明显影响。

### 3. Spark SQL 站点统计

文件：bigdata/ddl/04_spark_ads.sql

~~~sql
INSERT OVERWRITE DIRECTORY '/aq/ads/station_pollutant'
USING csv OPTIONS ('header' = 'true')
SELECT /*+ COALESCE(1) */ station, pollutant,
       ROUND(AVG(value), 2) AS avg_value,
       COUNT(value)         AS valid_cnt
FROM aq_long
GROUP BY station, pollutant;
~~~

**逐块解释：**

- INSERT OVERWRITE DIRECTORY：把查询结果写到 HDFS 目录，覆盖写，重跑不会翻倍。
- USING csv OPTIONS header=true：写成带表头的 CSV，方便后面导入。
- COALESCE(1) 提示：让结果合并成一个文件，避免 getmerge 后出现多个表头。
- GROUP BY station, pollutant：每个站点每种污染物一行。
- AVG(value)：只对非 NULL 求平均；COUNT(value)：只数非 NULL。

**为什么这么写：** 站点对比图需要"每个站点一根柱子"，所以按站点和污染物分组；同时输出有效样本数，页面 tooltip 可以显示这个平均值基于多少条数据。

**输入输出：** 输入 aq_long 视图（把 6 个污染物列转成行的长表）；输出 72 行 CSV。

**改错会怎样：** 如果按 station 分组但不带 pollutant，会把六种污染物混在一起平均，物理意义就错了；如果 COUNT(*) 而不是 COUNT(value)，有效样本数会变成总行数。

**可能追问：** ROUND 保留几位？——两位，和 MySQL 的 DECIMAL(10,2) 对齐。

### 8. 对应的 Service 方法

文件：backend/aqp-server/src/main/java/com/aqp/server/service/impl/StatsServiceImpl.java

~~~java
private static final List<String> ALLOWED =
        Arrays.asList("PM2.5", "PM10", "SO2", "NO2", "CO", "O3");

private String checkPollutant(String pollutant) {
    String value = (pollutant == null || pollutant.trim().isEmpty())
            ? "PM2.5" : pollutant.trim().toUpperCase();
    if (!ALLOWED.contains(value)) {
        throw new BizException(400, "不支持的污染物：" + pollutant
                + "，可选：" + String.join(",", ALLOWED));
    }
    return value;
}

@Override
public List<StationStatVO> stationStats(String pollutant) {
    return statsMapper.selectStationStats(checkPollutant(pollutant));
}
~~~

**逐块解释：**

- ALLOWED 是白名单，只允许这六种。
- 空值默认 PM2.5；输入统一转大写，避免用户传 pm2.5 匹配不上。
- 不在白名单就抛 BizException(400)。
- stationStats 先校验再查库，校验结果直接作为查询参数。

**为什么这么写：** 污染物是唯一的外部输入，如果直接拼进 SQL 有风险，先做成白名单最稳。

**输入输出：** 输入字符串 pollutant；输出校验后的规范值或异常。

**改错会怎样：** 不做校验的话，传个 ABC 会查出空列表，前端显示空白，用户以为是系统坏了；抛异常至少能提示可选值。

**可能追问：** 为什么不在 Controller 校验？——Controller 只负责协议层，参数的业务规则属于 Service。

}
~~~

**逐块解释：**

- baseURL 是 /api，所以请求 /stations 实际是 /api/stations，由 Vite 代理转给 8080。
- 成功拦截器判断 code，非 0 转成 rejected，页面 catch 能统一处理。
- 返回 body.data，页面拿到的直接是数组，不用每次写 res.data.data。
- params 对象会被 axios 拼成查询字符串。

**输入输出：** 输入污染物；输出 Promise，成功时是站点数组。

**改错会怎样：** 如果拦截器直接返回 res，页面就得自己判断 code、自己取 data，重复代码多；如果错误不 reject，页面会拿到 undefined 继续渲染。

**可能追问：** 超时设多少？——15 秒，正常接口毫秒级，设长一点是为了容忍首次启动。

### 11. 污染物切换与数据刷新

文件：frontend/src/views/Dashboard.vue

~~~js
const pollutant = ref('PM2.5')

async function loadCharts() {
  loading.value = true
  error.value = ''
  try {
    const [s, m, h] = await Promise.all([
      fetchStations(pollutant.value),
      fetchMonthly(pollutant.value),
      fetchHourly(pollutant.value)
    ])
    stations.value = s
    monthly.value = m
    hourly.value = h
  } catch (e) {
    error.value = '图表数据加载失败：' + e.message
    stations.value = []
    monthly.value = []
    hourly.value = []
  } finally {
    loading.value = false
  }
}

onMounted(() => { loadOverview(); loadCharts() })
watch(pollutant, () => { loadCharts() })
~~~

**逐块解释：**

- ref('PM2.5')：响应式变量，下拉框 v-model 绑的就是它。
- Promise.all：三个接口并行请求，比一个一个等快。
- 数组解构赋值给三个 ref，computed 的图表配置自动重算。
- catch 里清空数组，避免旧数据残留；finally 关 loading。
- onMounted 首屏加载一次，watch 在切换时再加载。

**输入输出：** 输入当前污染物；输出三组新数据，驱动三张图更新。

**改错会怎样：** 不写 watch 就换了选项图表不动；不写 finally 则失败后 loading 永远转圈。

**可能追问：** 为什么指标卡不跟着变？——指标卡是全局概览（站点数、污染物数、总样本），和单个污染物无关，所以只请求一次。

### 2. 为什么三张统计表行数不同

因为粒度不同：站点表是"12 个站点 × 6 种污染物"，月度表是"48 个月 × 6 种污染物"，小时表是"24 个小时 × 6 种污染物"。行数等于维度取值个数相乘。

### 3. 为什么平均值的分母是有效样本数，不是总记录数

缺失代表"没测到"，不代表"测得 0"。如果分母用总行数，相当于把没测到的小时按 0 浓度算进去，平均值会系统性偏低。项目里 AVG 只对非空值计算，同时输出 COUNT(非空) 作为 valid_cnt，让读数据的人知道这个均值基于多少条观测。

### 4. 为什么缺失值不能直接当 0

- 物理意义错误：0 μg/m³ 是"洁净空气"，缺失是"没测"，两者含义完全不同。
- 会拉低均值：CO 缺 4.92%，若按 0 算，CO 平均浓度会明显偏低。
- 会虚增样本：有效样本数会变成总行数，失去可信度。
- 会影响趋势：某段时间集中缺失时，折线图会出现不真实的"低谷"。

### 5. 为什么三种聚合的 PM2.5 样本数之和都是 412,029

三张表用的是同一批 PM2.5 非空记录，只是分组方式不同。按 12 个站点分、按 48 个月分、按 24 个小时分，分组后各组 COUNT 相加，等于全部非空记录数。这不是巧合，而是验证"没有重复计数、没有漏计"的手段。

### 6. 原始数据量、Hive 查询结果数、Spark 统计结果数有什么区别

| 口径 | 数字 | 含义 |
| --- | --- | --- |
| 原始记录 | 420,768 | 12 个 CSV 的行数，一行代表一个站点一个小时 |
| Hive 查询 COUNT(*) | 420,768 | 通过外部表读同一批文件得到的行数，应与原始一致 |
| Spark 统计结果 | 72 / 288 / 144 | 聚合后的"组数"，不是原始行数 |

老师如果问"为什么最后只剩几十行"，回答：明细变成了汇总，一条汇总记录背后是几千到几万条原始观测。

## 第七部分：常见错误与排查思路

> 排查原则：先看日志和返回内容，再判断原因；不要一上来就重装软件。

### 1. HDFS 或 Hive 服务没启动

**现象：** Spark 或 Hive 报连接失败，或者 HDFS 命令卡住。

**检查顺序：**

1. 虚拟机里执行 jps，看有没有 NameNode、DataNode、ResourceManager、NodeManager、RunJar。
2. 缺 NameNode 说明 HDFS 没起来；缺 RunJar 说明 Hive 元数据服务或 HiveServer2 没起来。
3. 看 /opt/hadoop/logs 和 /opt/hive/logs 下对应的日志。
4. 确认虚拟机磁盘没满（df -h）。

**不要做：** 上来就 format 或者删数据目录。

### 2. Hive 统计行数多出 12 条表头

**现象：** COUNT 得到 420,780。

**原因：** 某个引擎没跳过表头，通常是 Spark 读原表。

**检查顺序：**

1. 分别用 Hive 和 Spark 查同一张表，对比行数。
2. 查视图 ods_air_raw_v 的行数是不是 420,768。
3. 看 01_hive_ods.sql 里的 skip.header.line.count 和 02_hive_view.sql 里的 WHERE LOWER(no)。

### 3. NA 被错误处理成 0

**现象：** 平均值明显偏低，有效样本数等于总行数。

**检查顺序：**

1. 看 SQL 里是不是用了 IFNULL(字段, 0) 或者 COALESCE(字段, 0)。
2. 看是不是直接 SUM/COUNT(*) 而没有排除 NA。
3. 用一条查询验证：SELECT COUNT(*) FROM 表 WHERE co = 'NA'，应等于 20,701。

### 4. Spark 与 Hive 读取结果不一致

**原因：** 常见的三个：表头、NULL 处理、读的表不是同一张（原表 vs 视图）。

**检查顺序：** 先统一查视图，再对比 COUNT；再对比同一条 SQL 的 SUM 或 AVG。不要急着改数据。

### 5. MySQL 导入失败

**检查顺序：**

1. 看报错是语法错误还是权限错误。
2. 确认执行的是 data/interim/load_ads.sql，且文件是 UTF-8。
3. 确认当前账号对 aq_air 有建表权限（aq_user 是只读，导入要用 root）。
4. 确认 CSV 行数和 INSERT 的列数一致。

### 6. 后端 8080 端口被占用

**检查：** netstat -ano 找到 :8080 的 PID，看是哪个进程。

**处理：** 要么结束占用进程，要么在 application.yml 改端口（同时要改前端 Vite 代理的 target）。

### 7. 数据库认证失败

**现象：** 启动报 Access denied 或数据源初始化失败。

**检查顺序：**

1. MySQL80 服务是否运行。
2. backend/.env.local 是否存在、AQ_DB_PASSWORD 是否正确。
3. aq_user 是否只有三张表的 SELECT 权限（权限不足会报 1142）。

**不要做：** 把密码写进 application.yml 或提交到 Git。

### 8. 前端 5173 打不开

**检查：** npm run dev 的窗口是否还开着；node_modules 是否存在；端口是否被占用。

**处理：** 重新 npm install（依赖缺失时），或换端口启动。

### 9. Vite 代理失败

**现象：** 页面能开，但接口 404 或连接被拒。

**检查顺序：**

1. 后端 8080 是否在监听。
2. vite.config.js 里 proxy 的 target 是否是 http://127.0.0.1:8080。
3. 浏览器网络面板看请求地址是不是 /api/xxx（不是 8080/xxx）。

### 10. 图表没有数据、切换污染物不生效

**检查顺序：**

1. 浏览器控制台有没有报错。
2. 网络面板里 /api/stations 等请求是否发出、返回是否 200。
3. 返回的 data 是否为空数组。
4. Dashboard.vue 里 watch(pollutant) 是否还在，loadCharts 是否被调用。
5. BaseChart 的 option 是否为 null（没有数据时会返回 null，不渲染）。

## 第九部分：快速复习卡片

### 一、10 个最重要的技术概念

1. **HDFS**：分布式文件系统，本项目存原始 CSV 和统计结果。
2. **Hive 外部表**：只存元数据，删表不删数据，用 LOCATION 指向 HDFS 目录。
3. **OpenCSVSerde**：按 CSV 规则解析，能正确处理字段外的双引号。
4. **skip.header.line.count**：Hive 跳过表头，但 Spark 不认。
5. **视图**：本项目用视图过滤表头行，统一 Hive 和 Spark 的口径。
6. **GROUP BY**：按维度分组，本项目分站点、年月、小时三种。
7. **AVG 与 COUNT**：AVG 忽略 NULL，COUNT(字段) 只数非空，两者一起输出。
8. **三层架构**：Controller 接请求、Service 写业务、Mapper 查数据库。
9. **MyBatis 井号占位符**：预编译参数，防 SQL 注入。
10. **Vue 响应式与 watch**：pollutant 变化触发重新请求，computed 生成图表配置。
